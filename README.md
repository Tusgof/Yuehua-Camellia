# Camellia

Camellia เป็นห้องทดลองกลยุทธ์ลงทุนแบบใช้งานเร็ว เป้าหมายคือรับกลยุทธ์จากแหล่งที่เจ้าของติดตาม นำกติกามาเขียนให้ชัด ทดสอบย้อนหลังแบบพื้นฐาน แล้วพากลยุทธ์ที่ผ่านเกณฑ์ไปทดลองในพอร์ตจำลอง

Camellia ไม่ได้พยายามพิสูจน์ทฤษฎีใหม่แบบ Lily และไม่ใช้ระบบกำกับงานที่ซับซ้อนเกินความจำเป็น

## เส้นทางของกลยุทธ์

```text
ที่มาของกลยุทธ์
      ↓
กติกาที่เขียนชัดและหยุดแก้ชั่วคราว
      ↓
Backtest หลังหักต้นทุน
      ↓
ผ่าน ───────────────→ แผน Paper Trade → พอร์ตจำลอง → ทบทวน
  └─ ไม่ผ่าน → ปฏิเสธ หรือแก้สมมติฐานแล้วสร้างรุ่นใหม่
```

## หลักที่ห้ามตัดทิ้ง

1. บันทึกว่าแนวคิดมาจากใครและจากแหล่งใด
2. กำหนดกติกาซื้อ ขาย ขนาดสถานะ และเกณฑ์ผ่านก่อนเปิดดูผล
3. คำสั่งซื้อใน backtest ต้องเกิดหลังสัญญาณอย่างน้อยหนึ่งช่วงเวลา เพื่อไม่ใช้ข้อมูลอนาคต
4. รายงานผลก่อนและหลังค่าธรรมเนียม/ส่วนต่างราคา
5. แยกข้อมูลที่ใช้ปรับกลยุทธ์ออกจากช่วงตรวจสอบสุดท้ายตามลำดับเวลา
6. Paper trade คือการทดลอง ไม่ใช่หลักฐานว่ากลยุทธ์ทำกำไรจริง
7. การส่งคำสั่งเงินจริงอยู่นอกขอบเขต จนกว่าเจ้าของจะอนุมัติเป็นงานใหม่โดยชัดเจน

## เริ่มกลยุทธ์แรก

1. คัดลอก `strategies/STRATEGY_TEMPLATE.md` เป็น `strategies/<strategy_id>.md`
2. เพิ่มรายการใน `experiments/strategy_registry.json` ด้วยสถานะ `specified`
3. กำหนดเกณฑ์ผ่านและช่วงข้อมูลก่อนรัน backtest
4. บันทึกผลด้วย `reports/BACKTEST_REPORT_TEMPLATE.md`
5. ถ้าผ่าน จึงสร้างแผนจาก `paper_trading/PAPER_PLAN_TEMPLATE.md`

ตรวจสุขภาพโปรเจกต์ด้วย:

```powershell
python scripts/validate_project.py
python -m unittest discover -s tests -v
```

ดูสถานะและแผนล่าสุดที่ `PROJECT_BRAIN.md` และ `IMPLEMENT_PLAN.md`

คู่มือ Webull Thailand/OpenAPI และสถานะที่ยืนยันแล้วอยู่ที่ `docs/WEBULL_OPENAPI.md`
